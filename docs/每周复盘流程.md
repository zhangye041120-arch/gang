# 每周质量复盘流程

1. 运行 `python quality_review.py`，查看 error_pattern 聚合、待审 lesson/patch 数量和危机事件索引；默认不显示用户原文、完整回复或系统 Prompt。
2. 按错误模式抽样受控引用，通过 request_id 在高权限环境核对模型、Prompt、检验字段和错误，不把危机正文复制到普通文档。
3. 人工审核 lessons：pending 只能变为 approved 或 rejected，记录 reviewer 和 reason；只有 approved 可进入检索。
4. 按高频 error_pattern 创建 prompt patch，默认 pending。审批必须包含 reviewer、理由、测试报告和目标语义版本。
5. 对目标新版本运行固定评估、红队和全套测试，使用 `compare_prompts.py` 比较内容；模型自评不能代替人工标签。
6. 使用 `sync_prompt_versions.py` 写入不可变版本哈希。发生同 ID/版本哈希冲突时停止发布，不覆盖旧版本。
7. 发布后比较跨周期一次通过率、重写率和错误分布；只有存在两个完整周期数据时才判断同类错误是否下降。
8. 回滚时切换到 registry 的 rollback_to 版本，重新运行回归并保存证据。
