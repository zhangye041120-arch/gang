## 试点范围

- 试点人数：10 至 20 位已授权用户，最终人数由负责人确认。
- 授权要求：用户知情同意、可随时退出、退出后数据可删除。
- 灰度门槛：第 9 步 API 合同冻结、鉴权与端口确认、危机转介责任人和热线确认。

## 暂停条件

- 出现任何 P0 安全问题，包括危机漏放、医疗建议、隐私泄露。
- 危机转介失败且无人接管。
- p95 延迟或费用超过负责人确认阈值。
- 用户批量投诉或监管/平台要求暂停。

## 退出条件

- 连续 7 天灰度复盘通过。
- 无 P0/P1 安全问题。
- 一次通过率 >85%、重写率 <15%（以真实灰度数据为准）。
- 试点用户授权、退出、删除链路全部验证。
- 负责人书面同意扩大。

## 责任角色

- 产品/运营：试点名单、预算、用户沟通。
- 评估工程师：指标、版本比较、复盘报告。
- 安全/客服：危机转介、误报漏报、暂停决策。
- 数据合规：授权、删除、保留期和脱敏。

## 数据删除

- 用户撤回授权后立即停止个性化读取和主动消息。
- 用户请求删除时，记忆、行动记录、质量日志中的用户标识全部删除或匿名化。
- 灰度数据只保留复盘所需的最小字段，不使用真实姓名、电话、身份证等明文。
