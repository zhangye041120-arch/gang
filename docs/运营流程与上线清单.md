# 运营流程与上线清单

本文合并每周复盘、Prompt 发布、上线前置动作、主动问候策略和危机演练模板。

## 每周质量复盘流程

1. 运行 `python scripts/运维工具.py quality-review`，查看 error_pattern 聚合、待审 lesson/patch 数量和危机事件索引；默认不显示用户原文、完整回复或系统 Prompt。
2. 按错误模式抽样受控引用，通过 request_id 在高权限环境核对模型、Prompt、检验字段和错误，不把危机正文复制到普通文档。
3. 人工审核 lessons：pending 只能变为 approved 或 rejected，记录 reviewer 和 reason；只有 approved 可进入检索。
4. 按高频 error_pattern 创建 prompt patch，默认 pending。审批必须包含 reviewer、理由、测试报告和目标语义版本。
5. 对目标新版本运行固定评估、红队和全套测试，使用 `scripts/运维工具.py compare-prompts` 比较内容；模型自评不能代替人工标签。
6. 使用 `scripts/运维工具.py sync-prompts` 写入不可变版本哈希。发生同 ID/版本哈希冲突时停止发布，不覆盖旧版本。
7. 发布后比较跨周期一次通过率、重写率和错误分布；只有存在两个完整周期数据时才判断同类错误是否下降。
8. 回滚时切换到 registry 的 rollback_to 版本，重新运行回归并保存证据。

## Prompt 发布流程

1. **提出**：新建不可变的语义版本内容文件，补充 `prompt_versions/registry.json` 的 owner、scope、changelog、创建时间和 rollback_to；不覆盖旧文件。
2. **测试**：运行 Prompt 静态检查、结构化 Schema 测试和 `prompt_regression_v1.json` 高风险回归。人工标签只能使用 `pass`、`fail`、`needs_review`，不能由模型自评充当人工通过。
3. **比较**：使用 `python scripts/运维工具.py compare-prompts main-agent 0.9.0 1.0.0` 输出版本差异，并人工审查禁用表达、行动白名单、注入边界和安全话术变化。
4. **审批**：由 Prompt owner 和安全负责人确认测试报告、差异和回滚版本；未审批版本保持不可选。
5. **发布**：在 `.env` 中显式设置 `PROMPT_VERSION`，启动时解析不到版本则拒绝启动，不静默回退到未知版本。
6. **监控**：记录 Prompt 版本、重写率、硬拦截率、非法 JSON 和高风险回归结果；本轮不建设日志平台。
7. **回滚**：把 `PROMPT_VERSION` 改为 registry 中的 `rollback_to` 版本，重新运行全套测试和高风险回归后再启动服务。

当前默认版本为 `1.7.0`，回滚点为 `1.6.0`；旧版本继续保留各自回滚点。文件型 registry 可在后续迁移到数据库，但旧版本内容不得覆盖。

## 小辽 M7 上线前置动作清单

目标：从“可进入受限试点”推进到“可发布完整 M7”。

原则：每项都必须有真实证据；模板、Mock、配置占位不算完成。

### 1. 55 条主链路真实模型评估

完成状态：2026-08-07 已执行，53/55，硬性安全漏放 0。

动作：

1. 确认评估预算和费用负责人。
2. 运行主链路真实评估：

```bash
python 运行评估套件.py --direct --real-approved-by "你的姓名/角色" --out eval_runs --run-id run-real-main-v1
```

或通过 API 运行：

```bash
python 运行评估套件.py --http --real-approved-by "你的姓名/角色" --base-url http://127.0.0.1:8081 --token "$API_TOKEN" --out eval_runs --run-id run-real-main-v1
```

3. 验收目标：
   - 一次通过率 > 85%
   - 重写率 < 15%
   - 硬性安全漏放 = 0
4. 把 `metrics.json` 和失败用例保存为不可变评估运行，并记录在本清单。

### 2. 真实 7 天灰度

动作：

1. 由产品/运营确认 10-20 位授权试点用户。
2. 每位用户完成知情同意，确认可退出、可删除。
3. 按 [7天灰度方案.md](7天灰度方案.md) 部署受限试点。
4. 每天填写复盘表：用户数、对话数、一次通过率、重写率、拦截率、硬漏放、P0/P1、费用。
5. 连续 7 天无 P0/P1 且指标达标后，由负责人书面同意扩大。

### 3. 真实企微消息闭环

动作：

1. 外部团队提供：
   - CorpID、AgentId、Secret
   - 回调 URL、`WECOM_CALLBACK_TOKEN`、`WECOM_ENCODING_AES_KEY`
   - 客服消息/应用消息发送权限
2. 配置到 `.env`，并确认 Java 后端负责验签、解密、去重。
3. Java 后端调用 `POST /v1/chat`，回复只由 Java/企微发送层发出。
4. 按 [企微联调检查单.md](企微联调检查单.md) 逐项勾选，保存真实消息截图/日志作为证据。
5. 员工群每日签到提醒：配置群机器人 Webhook 与
   `WECOM_CHECKIN_GROUP_*` 变量，按
   [签到提醒策略.md](签到提醒策略.md) 完成一次真实发送验证。

### 4. 真实危机转介

动作：

1. 确认各地区真实热线、值班人、授权规则和误报处理流程。
2. 把真实配置写入危机转介配置：

```json
{
  "default_region": "华东",
  "routes": {
    "华东": {
      "region": "华东",
      "hotline": "真实热线",
      "on_call": "真实值班人",
      "authorization_required": true
    }
  }
}
```

3. 设置 `CRISIS_REFERRAL_CONFIG_PATH` 指向该文件。
4. 完成至少一次真实危机演练，按 [危机演练记录.md](危机演练记录.md) 填写真实字段。

### 5. 监控与告警

动作：

1. 确认费用预算、p95 延迟目标、5xx 阈值、队列积压阈值。
2. 接入真实监控/告警平台。
3. 把 [monitoring/alert_rules.json](../monitoring/alert_rules.json) 中的 `待确认` 改为已确认阈值。
4. 验证至少一条真实告警能触发并通知到负责人。

### 6. Java 合同与 action 冻结

动作：

1. Java 负责人确认鉴权方案、生产端口、六值 intent。
2. Java/前端确认 M1/M2/M3/M5 页面和 params。
3. 更新 `ACTION_WHITELIST_VERSION`，去掉 `pending-java-confirmation`。
4. 在本清单记录 action 冻结状态。

### 7. 发布包安全

动作：

1. 打包前确认 `.env`、`.env.docker`、任何日志和密钥不进入制品。
2. 用密钥扫描工具跑一遍，只允许出现 `.env.example` 等占位文件。
3. 发布包内不包含真实用户原文、危机原文或未脱敏日志。
4. 运行 `python scripts/验证发布.py --gate`，保存退出码与 CI 链接。
5. 运行 `docker image inspect`，确认运行用户为 `10001:10001`；检查镜像内不存在
   `.env`、`.git`、tests、日志或 SQLite 数据。

### 8. 备份与恢复演练

1. 使用 `scripts/备份数据库.py` 生成 age 加密备份，备份目录由部署环境限制权限。
2. 使用 `scripts/恢复数据库.py` 恢复到名称不同的一次性数据库；脚本禁止覆盖源库。
3. 在恢复库执行迁移账本、知识块数量、记忆/行动/删除墓碑抽样核验。
4. 记录备份时间、密文校验值、恢复耗时、验证人和销毁恢复库的变更单。

### 9. 最终判定

动作：

1. 重新运行 `python -m pytest -q --tb=short`。
2. 运行 `python 运行评估套件.py --offline` 和 `python 运行RAG评估.py --offline`。
3. 把最终判定写入本清单。
4. 只有当上述自动门禁和外部人工项目全部有真实证据后，才能判定“可发布完整 M7”。

## 小辽 M7 主动问候策略

状态：策略已配置化，默认关闭。

### 配置项

| 配置 | 默认值 | 说明 |
|---|---|---|
| `WECOM_ACTIVE_GREETING_ENABLED` | `false` | 全局开关，默认关闭 |
| `WECOM_ACTIVE_GREETING_MAX_PER_DAY` | `1` | 单用户每日主动问候上限 |
| `WECOM_ACTIVE_GREETING_RECENT_ACTIVE_HOURS` | `24` | 最近活跃时间窗口 |
| `WECOM_DEDUP_RETENTION_HOURS` | `168` | 事件去重保留期 |

### 发送条件

同时满足才允许发送：

- 全局开关开启
- 用户未关闭主动问候
- `personalization` 授权存在
- 主动消息授权存在
- 不在免打扰时段
- 最近活跃窗口内未与用户互动
- 当日未达到频率上限
- 情绪趋势未低于低阈值

用户撤回授权或主动关闭后，策略立即返回 `blocked`，不会发送主动问候，也不会读取个性化记忆。
