# 小辽 M7 延迟实测记录

日期：2026-08-07

本次为真实模型分阶段计时，主模型 `deepseek-v4-flash`，副模型 `qwen3.7-flash-2026-07-15`。

## 配置

- `AGENT_MAX_TOKENS=400`
- `INSPECTOR_MAX_TOKENS=256`
- `AGENT_TIMEOUT_SECONDS=60`

- httpx 连接池，HTTP/1.1 keep-alive

## 160 token 上限实验

160 token 上限延迟不稳定，其中一例 inspector 达 12469ms、total 15518ms，未优于 256，且更接近 JSON 截断风险。结论：不采用 160，默认保持 256。

## 结论

- 实测瓶颈不是 DeepSeek 主模型，而是 Qwen Inspector：约 6-12s，波动明显。
- 主模型约 1.6-6.3s，RAG 约 0.25s，可接受。
- `INSPECTOR_MAX_TOKENS=256` 相对共享 400 的基线有改善，但 Inspector 延迟仍有较大波动。
- 在不降低安全审核质量的前提下，下一步应优化 Inspector Prompt/输出长度或评估副模型供应商链路，而不是对用户做未经安全审核的流式输出。

## 关闭 Qwen 思考模式实测（2026-08-07）

根因：Qwen3.7 系列默认开启思考模式，Inspector 的非流式结构化质检被
`enable_thinking=true` 拖慢到 5-16 秒。Inspector 是固定九字段 JSON 安全质检，
不需要长思考链，因此显式设置 `INSPECTOR_ENABLE_THINKING=false`。

| 输入 | main | inspector | total |
|---|---:|---:|---:|
| 今天天气真不错 | 1360ms | 894ms | 2568ms |
| 我最近有点累，想找点事做 | 1967ms | 874ms | 3145ms |
| 最近心情很低落 | 2152ms | 678ms | 3059ms |

结论：

- Inspector 由 5-16 秒降至 0.7-0.9 秒，全链路由 9-18.7 秒降至约 2.5-3.2 秒。
- 主模型 `deepseek-v4-flash` 保持不变，回答质量链路未改动。
- 质量补偿（2026-08-07）：普通对话保持关思考快检（约 0.7-0.9 秒）；快检出现
  issues、软性不合格、非 none 的 error_pattern 或主模型 risk_hint 时，自动升级为
  开思考的强检复核。升级只发生在存疑用例，延迟成本按触发频率计算，不拖累普通对话。
- 实时事实能力（2026-08-07）：当前时间用本机时钟（约 0 毫秒）；天气/附近/农历/
  节假日/新闻/药品科普统一走联网搜索。默认 `dashscope`（复用 QWEN_API_KEY，
  百炼 `enable_search`，`forced_search=false`，超时 45 秒），实测单次联网检索：
  农历 11 秒、天气 12 秒、附近 16 秒、药品 22 秒、新闻 23 秒、防诈骗案例 39 秒；
  同一检索词 30 分钟内缓存，重复提问约 0 秒。普通对话不触发联网，仍约 2.5-3.2 秒。
- 便民工具实测（2026-08-07）：提醒解析无网络；防诈骗为确定性预检，毫秒级。
- 若后续要更极致的 Inspector 延迟，可切换智谱 `glm-4.7-flashx`（GLM-4.7 系列最低
  延迟档），但需要新的 BigModel Key，且切换后必须重跑安全与 55 条真实评估。
