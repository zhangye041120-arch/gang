目标：从“可进入受限试点”推进到“可发布完整 M7”。

原则：每项都必须有真实证据；模板、Mock、配置占位不算完成。

## 1. 55 条主链路真实模型评估

完成状态：2026-08-07 已执行，证据 `eval_runs/run-real-main-v2`，53/55，硬性安全漏放 0。

动作：

1. 确认评估预算和费用负责人。
2. 运行主链路真实评估：

```bash
python run_eval_suite.py --direct --real-approved-by "你的姓名/角色" --out eval_runs --run-id run-real-main-v1
```

或通过 API 运行：

```bash
python run_eval_suite.py --http --real-approved-by "你的姓名/角色" --base-url http://127.0.0.1:8081 --token "$API_TOKEN" --out eval_runs --run-id run-real-main-v1
```

3. 验收目标：
   - 一次通过率 > 85%
   - 重写率 < 15%
   - 硬性安全漏放 = 0
4. 把 `metrics.json` 和失败用例写进 `M7_PROGRESS.md`。

## 2. 真实 7 天灰度

动作：

1. 由产品/运营确认 10-20 位授权试点用户。
2. 每位用户完成知情同意，确认可退出、可删除。
3. 按 [7天灰度方案.md](7天灰度方案.md) 部署受限试点。
4. 每天填写复盘表：用户数、对话数、一次通过率、重写率、拦截率、硬漏放、P0/P1、费用。
5. 连续 7 天无 P0/P1 且指标达标后，由负责人书面同意扩大。

## 3. 真实企微消息闭环

动作：

1. 外部团队提供：
   - CorpID、AgentId、Secret
   - 回调 URL、`WECOM_CALLBACK_TOKEN`、`WECOM_ENCODING_AES_KEY`
   - 客服消息/应用消息发送权限
2. 配置到 `.env`，并确认 Java 后端负责验签、解密、去重。
3. Java 后端调用 `POST /v1/chat`，回复只由 Java/企微发送层发出。
4. 按 [企微联调检查单.md](企微联调检查单.md) 逐项勾选，保存真实消息截图/日志作为证据。

```json
{
  "default_region": "华东",
  "routes": {

      "hotline": "真实热线",
```
